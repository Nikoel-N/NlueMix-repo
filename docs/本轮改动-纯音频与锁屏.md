# 本轮改动：纯音频模式 + 锁屏继续串流

时间：2026-10-12　　版本：客户端 0.1.0 → **0.2.0**

---

## 一、学的是什么

App-Scrcpy 的模式表里有一条值得抄：

| 模式 | 投屏 | 系统音频 | 远程控制 | 锁屏可用 |
|---|---|---|---|---|
| 画面 + 控制 + 音频 | 是 | 是 | 是 | **否** |
| **纯音频** | **否** | **是** | 否 | **是** |

差别就在**"有没有投屏画面"**：一旦有画面，息屏就等于投屏结束，
很多 ROM 会顺手把整个 MediaProjection 会话（含音频）一起收掉。
纯音频不需要画面，不建虚显反而更稳。

## 二、改了什么

### 2.1 手机端（APK）

**（1）纯音频模式：不建虚拟显示器**

`CaptureService.kt` — `ensureVirtualDisplay()`：

    if (audioOnlyMode) {
        broadcast("STEP", "纯音频模式：不创建虚拟显示器（锁屏可继续）")
        return true
    }

默认开启，可通过 `--ez audio_only false` 关掉。
Android 14+ 只要求前台服务类型是 mediaProjection 且回调已注册，不要求必须有虚显。

**（2）CPU 唤醒锁**

锁屏后系统让 CPU 休眠，`AudioRecord.read()` 拿不到数据 → 表现就是"亮屏有声、锁屏就断"。

`CaptureService.kt` 新增 `acquireWakeLock()` / `releaseWakeLock()`：

    PARTIAL_WAKE_LOCK，tag = "NlueMix:capture"，上限 6 小时（防泄漏）
    获取点：startAdaptiveCapture()
    释放点：stopEverything()  ← 所有停止路径的唯一出口

**（3）清单改动**

    <uses-permission android:name="android.permission.WAKE_LOCK" />
    <uses-permission android:name="android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS" />
    <service ... android:stopWithTask="false" />   ← 从最近任务划掉也不停

### 2.2 shell 采集端（nluemix-server.jar）

**（1）同样的唤醒锁**

先实测确认 shell（uid 2000）确实有权限：

    adb shell dumpsys package com.android.shell | grep WAKE_LOCK
      android.permission.WAKE_LOCK: granted=true
      android.permission.CAPTURE_AUDIO_OUTPUT: granted=true

app_process 没有 Context，PowerManager 是隐藏 API，所以走
`ActivityThread.systemMain()` 反射拿系统 Context —— 全程 try/catch，
失败只是少一层保险，不影响采集，并如实打日志。

**（2）每 5 秒一行统计**（锁屏测试需要它来判断到底还在不在传）

    nluemix-server: [统计] 50 包/秒, 峰值=32154, 非零=99%, 累计=1234567 字节

jar 体积 4505 → 5158 字节。

### 2.3 电脑端（0.1.0 → 0.2.0）

**失败提示改为分情况诊断。** 这是本轮实测踩到的真实故障：

    现象：手机 ping 得通，但 adb 设备列表空、mDNS 也发现不到
    原因：手机的「无线调试」被系统关掉了（息屏或系统清理都会）
    旧提示：「没有检测到手机。请二选一：…」  ← 用户不知道该去哪儿修

现在会先 ping 一下手机，再决定说什么：

    手机在线  → 「手机 x.x.x.x 在线，但连不上它的调试端口。
                 说明「无线调试」被关掉了。请重新打开：
                 设置 → 更多设置 → 开发者选项 → 无线调试」
    手机不在线 → 原来的「请二选一」提示

新增 `IsHostReachable()`：3 次 ICMP，单次 500 ms，最多约 1.5 秒，不会卡界面。

## 四、还没验证的（如实标注）

**锁屏后到底能不能持续出声，我还没实测成功。**

卡在：手机的「无线调试」当前是关闭状态，

    手机 192.168.1.6        → ping 通（在线）
    无线调试端口 46479/33227/5555/37000/40000 → 全部关闭
    adb mdns services       → 空

没有 adb 就没法启动 shell 采集端，所以这一步的实测要等无线调试重新打开。

代码层面该做的都做了（不建虚显 + 唤醒锁 + stopWithTask=false + 电池白名单），
但**在实测通过之前，不能声称"锁屏已经没问题"**。
