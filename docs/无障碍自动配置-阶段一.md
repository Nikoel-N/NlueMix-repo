## 二、闭环长什么样

    手机端（无障碍，用户点两下）
      1. 打开开发者选项页面
      2. 找到「无线调试」点进去
      3. 读出「IP 地址和端口」
      4. 存进 SharedPreferences

    用户点「开始串流」→ App 路径连上电脑（这条路本来就不需要 adb）
      5. 连上后把端口通过控制通道发给电脑

    电脑端
      6. 收到 AUTOCFG → adb pair（如需要）→ adb connect
      7. 之后即可走 shell 路径，采集 B 站这类没声明允许采集的应用

**关键设计**：App 路径充当「引导通道」—— 它零调试就能连上，
正好用它把 adb 需要的端口送过去，形成「先连上、再自动升级」的闭环。

## 三、这一阶段实测到了什么

### 3.1 链路验证（用模拟消息打真机协议）

    握手        手机已接入：测试手机（PCM 无损，48000 Hz/2 ch）→ 位置 1        ✓
    消息解析    [自动配置] 收到手机上报：192.168.1.6:59999（无需配对）        ✓
    adb 真执行  adb connect 192.168.1.6:59999 → cannot connect ... (10061)   ✓
    错误可读    可能原因：无线调试被关掉了，或者端口又变了                     ✓
    容错        AUTOCFG\t坏数据  → 「消息格式不对」，没崩                      ✓
    容错        端口 0           → 「连接端口无效」，没崩                      ✓

### 3.2 顺带测出一个真缺陷（已修）

**症状**：adb 的中文输出全是乱码 ——

    修之前：由于目标计算机积极拒绝，无法连接  →  鐢变簬鐩爣璁＄畻鏈虹Н鏋佹嫆缁濓紝鏃犳硶杩炴帴

**根因**（用原始字节判定的，不是猜的）：

    adb 输出字节：E7 94 B1        ← 这是「由」的 UTF-8 编码
    按 UTF-8 解码：由于目标计算机积极拒绝，无法连接。   ✓
    按 GBK  解码：鐢变簬鐩爣璁＄畻鏈虹Н鏋佹嫆缁濓紝…      ✗

`.NET` 的 `ProcessStartInfo` 没指定 `StandardOutputEncoding` 时，
按系统 OEM 代码页解码（中文系统是 GBK），而 adb 输出的是 UTF-8。

**影响范围**：所有 adb 提示 —— 配对失败、连接失败、设备列表、无线调试报错。
用户看到这些乱码等于没有提示，所以这是个必须修的缺陷。

**修法**：两个 `RunAdb` 都显式指定 `Encoding.UTF8`。

**特别注意**：`UsbAudioSource.cs` 里还有一处重定向 stdout，
那是 `adb exec-out` 出来的 **PCM 二进制流**，**绝不能设编码** ——
设了会把音频数据毁掉。这一点在代码注释里写明了。

修后验证：

    adb connect 192.168.1.6:59999 → cannot connect to 192.168.1.6:59999: 由于目标计算机积极拒绝，无法连接。 (10061)

## 六、合规提醒（别忘了）

无障碍功能按之前定的原则实现：

- **默认关闭**，用户在向导页主动去系统设置里开
- **只做必要的事**：配置里没有 `flagRequestFilterKeyEvents`，也不监听文本变化，
  因此拿不到输入框里逐字输入的内容（含密码）
- **不缓存、不上传**任何屏幕内容
- **可随时关闭**，关掉后手动配置仍可用
- 系统无障碍设置页里的说明文字如实写了它做什么、不做什么
